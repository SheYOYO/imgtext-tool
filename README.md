# 本地离线图片文字替换桌面工具

一个**完全本地运行、不联网、不上传图片**的桌面工具：上传图片后，用鼠标框选原图中的文字区域，程序自动提取原文字的颜色、字号、字间距、行间距、粗细、倾斜角度、清晰度与边缘噪点，用 OpenCV 擦除旧文字，在内置常用免费字体库中生成最接近的字体预览，供你选择与微调，最终让新文字「看起来像原图本来就是这个字」。

---


## 一、功能特性

- 上传本地图片并显示
- **画布缩放 / 平移 / 框选三件套**：
  - 鼠标滚轮缩放（带锚点缩放，光标位置固定）
  - 鼠标右键拖拽平移（放大后可拖动查看细节）
  - 鼠标左键拖拽框选文字修改区域（支持**多次框选多次替换**）
  - 「适应窗口」「100%」「缩小」「放大」一键按钮
  - 左下角实时显示「缩放 86% · 图像 (1920×1080)」状态
- **选区可二次编辑（8 锚点缩放 + 长摁移动 + 右上角叉号）**：矩形框拖拽**四角**斜向缩放、拖**四边中点**单独调高/调宽；**长摁（260ms）或明显拖动选框中间可整体移动**（单击框内=编辑文字，防误触）；长摁移动松手后右上角出现**叉号**（此时锚点收起，点叉号删除该框），单击选框恢复锚点。删除/移走选框后**原文字不再复活**（仅撤销可撤回）
- **新建选框即去除底字**：框选一片区域后，被遮住的原图文字就是想去除的文字，**松手即直接从工作图抹掉**（无需输入或确认）；之后无论删除选框还是移走选框都不再出现，**只有「撤销」能恢复**。框在纯背景区域不误擦。OCR 识别出的原文**只作输入框建议、不会被自动渲染回图上**（否则看起来像「没删掉」）——只有用户改字或点「确认替换文字」才生成替换预览。**擦除动作排在 OCR/特征/字体匹配长链路之前执行**，识别环节即便异常也绝不会阻断已完成的删字（异常只提示、UI 不崩）。
- **四边延长辅助线**：活动选框的上/下/左/右四条边向画布两端延伸出贯穿虚线的对齐参考线，方便把选框的行列与周围上下文文字对齐
- **擦除严格限制在选框内**：擦除范围就是**选框矩形本身**，框外的上下文文字/纹理一个像素都不动；且只在两个时机生效——**新建选框**（松手即擦）、**移动选框**。缩放选框（拖 8 锚点）、点选/重选/预览/应用一律不擦除；**复制选框也不擦除**（副本落点底下盖的是别处内容，不该被凭空抹掉）
- **替换文字智能参考线（PPT 式，主画布 + 预览都有）**：输入/确认替换文字时，在文字周围显示两层参考线，且**只叠加在显示层、确定替换 / 导出成品绝不出现**：
  - **①常驻「井」字辅助框**：四根贯穿整幅的虚线围住替换文字（相邻相交成井字），随时帮您目测与四周上下文对齐；
  - **②PPT 式智能对齐线**：当替换文字的对齐基准（左/中/右/上/中/下）接近**画布中线 / 其它选框 / 邻近文字**的对应边时，自动**吸附平移**到该参考线，并在对应位置闪现一条贯穿整幅的**品红实线**表示该处已对齐（类似 PPT 智能参考线）。不对齐时不画。
- **双缓冲绘图**：先把「图像+选区+手柄」画到离屏缓冲再一次性贴到画布，彻底消除黑屏、闪烁、渲染卡死、图像消失
- **快捷键**：`Ctrl+Z` 撤销、`Ctrl+Y` / `Ctrl+Shift+Z` **恢复**、`Ctrl+D` 复制选框、`Delete` 删除当前选中框
- **实时预览面板**：所有参数变化后 200ms 防抖自动刷新预览，无需手动点按钮
- **独立预览窗口**：调大看细节
- **全自动模式（默认开启）**：框选后程序自动完整提取全部视觉参数——文字颜色、字号高度、笔画粗细、字间距、行间距、倾斜角度、边缘抗锯齿、模糊程度、截图噪点质感——并**自动读取 `fonts/` 目录全部字体、直接选相似度最高的那一款**，自动按原图清晰度/颗粒质感渲染，默认一键出效果，**几乎无需手动调滑杆**；如需精修，仍可用右侧微调面板（含「恢复自动参数」按钮随时回到自动值）
- 自动提取：文字颜色、字号、字间距、行间距、粗细、倾斜角度、清晰度、抗锯齿、模糊程度、噪点质感
- 吸管取色 / 颜色选择器
- 旧文字用 OpenCV 图像修复（inpainting）擦除，还原背景纹理/渐变/噪点
- 内置常用免费字体库 + 自动扫描 `fonts/` 目录全部字体，按字形/粗细/宽高比/笔画特征计算相似度，给出 3~6 个候选
- 新文字渲染匹配颜色、字号、间距、倾斜、粗细、清晰度、边缘抗锯齿，可加轻微噪点/压缩感
- 中文路径兼容保存（绕过 OpenCV 非 ASCII 路径限制）
- 导出新图片（PNG/JPG/BMP）

## 二、依赖安装

**要求 Python 3.10+（需带 tkinter，标准安装版自带）。**

```bash
cd imgtext_tool
python -m venv .venv
# Windows 激活：
.venv\Scripts\activate
# Linux/macOS 激活：
source .venv/bin/activate

pip install -r requirements.txt
```

依赖清单（`requirements.txt`）：

```
opencv-python-headless>=4.8.0
numpy>=1.24.0
pillow>=10.0.0
```

> 使用 `opencv-python-headless`（无 GUI 的 OpenCV），避免与 tkinter 冲突；GUI 完全由 tkinter 负责。

## 四、内置字体配置说明

### 字体库方案

本工具**不做全网字体识别，不识别小众/付费字体**，只在内置常用免费字体池中做相似度匹配。

内置字体池（`app/config.py` 的 `FONT_POOL`）：

| 字体                     | 类型    | 说明                                |
| ---------------------- | ----- | --------------------------------- |
| 思源黑体                   | 中文黑体  | Source Han Sans / Noto Sans CJK   |
| 思源宋体                   | 中文宋体  | Source Han Serif / Noto Serif CJK |
| 微软雅黑                   | 中文黑体  | msyh（Windows 自带）                  |
| 系统宋体                   | 中文宋体  | simsun（Windows 自带）                |
| 系统黑体                   | 中文黑体  | simhei（Windows 自带）                |
| 等线                     | 中文黑体  | DengXian（Windows 自带）              |
| Arial / Arial Bold     | 英文无衬线 | Windows 自带                        |
| Calibri / Calibri Bold | 英文无衬线 | Windows 自带                        |
| Verdana                | 英文无衬线 | Windows 自带                        |
| Times New Roman / Bold | 英文衬线  | Windows 自带                        |

### 字体查找顺序

1. 优先用项目 `fonts/` 目录下放置的字体文件（**启动时自动扫描**该目录下的全部 `.ttf`/`.otf`）；
2. 其次用 `app/config.py` 内置字体池；
3. 都没有则跳过该字体。

### 如何添加自定义字体

直接把 `.ttf` / `.otf` 字体文件丢进 `fonts/` 目录即可——下次启动程序会自动把它加入候选字体池，无需改代码。如果还想让该字体在池里**标注中英文与粗细**，可在 `app/config.py` 的 `FONT_POOL` 中追加一条：

```python
{"name": "你的字体", "files": ["YourFont.ttf"], "cn": True, "weight": "regular"},
```

## 五、使用教程

### 5.1 画布操作（鼠标交互）

| 操作                   | 效果                    | 适用场景        |
| -------------------- | --------------------- | ----------- |
| **鼠标滚轮向上**           | 放大（光标位置固定，最小步进 10%）   | 看清细节后精准框选   |
| **鼠标滚轮向下**           | 缩小                    | 缩小看整体       |
| **按住鼠标右键拖动**         | 平移画面                  | 放大后查看图片其他区域 |
| **按住 `空格` + 鼠标右键拖拽选框中间** | **复制该选框到拖到的位置**（文字/字体/特征一起复制，**不擦除原图**） | 同一段文字多处出现时快速复用 |
| **按住鼠标左键拖动（空白处）**    | 框选新的文字修改区域            | 框选单段文字      |
| **按住鼠标左键拖动（已有框内）**   | **仅选中该选区（位置已锁定，不平移）** | 切换/编辑某个选区   |
| **按住鼠标左键拖拽选区四个边角手柄** | **缩放调整选区大小（其余角固定）**   | 微调选区范围      |
| **左键单击（不拖动）**        | 触发吸管取色                | 取色微调        |
| **`Ctrl+Z`**         | 撤销上一步               | 回退修改        |
| **`Ctrl+Y` / `Ctrl+Shift+Z`** | **恢复**刚撤销的一步      | 反悔，重做回来      |
| **`Delete`**         | 删除当前选中的选区             | 去掉误框的选区     |
| 「适应窗口」按钮             | 把图片缩放到当前画布大小          | 重置视图        |
| 「100%」按钮             | 缩放到原始像素（1:1）          | 1:1 精准编辑    |
| 「缩小 / 放大」按钮          | 缩放步进 0.2              | 微调缩放        |
| 「重置视图」按钮             | 回到适应窗口状态              | 撤销所有平移缩放    |

> **建议流程**：高分辨率原图 → 先点「适应窗口」看整体 → 滚轮放大到能看清文字 → 右键拖动平移到目标区域 → 左键框选 → 程序全自动出效果 → 不满意再微调。

> **双缓冲说明**：画布重绘时先把整幅画面（图像 + 选区框 + 手柄）画到一张离屏图，再一次性贴到画布，因此不会出现半幅图、黑屏、闪烁或图像消失；高倍放大时只光栅化当前可见区域，内存可控、不卡死。


### 5.2 文字替换流程（全自动，强制五步顺序）

1. 点击 **「上传图片」**，选择本地图片（PNG / JPG / BMP / WebP）。
2. 用滚轮/平移/缩放定位到目标文字，**左键拖拽框选**该区域。
3. 程序**全自动**按**强制五步顺序**完成（流程不可乱序，每步职责清晰）：

   **第一步（识别框内原文）：OCR 识别 + 采集特征 + 特征锁定**
   - 用本地离线 RapidOCR 引擎识别选区内的文字内容，自动填入「替换文字」输入框；
   - OCR 仅在**新建选区**时触发一次，识别结果作为默认替换文字（不覆盖用户手动改过的字）；
   - **特征采集**：提取本选区文字的**主要特征**（颜色 / 字号 / 字间距 / 笔画粗细 / 倾斜 / 清晰度 / 噪点），并**应用到新编辑文字**；
   - **OCR 小图放大**：选区图像高度 `<40px` 时自动 `cv2.resize` 放大（`INTER_CUBIC`）后再识别，显著提升小字识别准确率（修复识别不准）；
   - **特征锁定（`_locked`）**：确定文字特征后**立即冻结**，与该选区的**位置一同固定**——之后重选/缩放该框都**只恢复、绝不重新提取或重识别**，保证特征稳定；
   - OCR 引擎不可用时（如未安装 RapidOCR）优雅降级：不崩溃、不清空，仍保留手动输入，后续流程照常。
   **第二步（采集四周上下文样式）：四向参照校准**
   - 提取选区**上 / 下 / 左 / 右紧邻文字**作为样式参照样本，四向窗口各自**独立**扫描像素提取视觉参数；
   - 仅保留含文字的参照（无文字方向自动跳过，不越界、不污染）；
   - 用四向参照把本选区的**字号 / 字间距 / 笔画粗细（含骨架细化口径）/ 模糊 / 噪点**对齐到周围上下文风格（取融合值），确保替换文字与周边文字排版一致、质感统一；
   - 文字**颜色**保留选区自身（替换落在原位置，颜色以该位置为准）；
   - 回传各命中窗口文字的**整图坐标矩形**（`neighbor_boxes`），供第四步防重叠使用。
   **第三步（用户输入文字并确认）：键入文字，点击「确认替换文字」**
   - 在「替换文字」输入框修改/输入新文字（**输入法选词异常已修复**：输入框绑定实时回写，输入法组合输入不丢字、不串框）；
   - 点击 **「确认替换文字」** 按钮：锁定 `_confirmed=True` + `optimized=True`，触发**二次排版优化 + 防重叠渲染**并立即刷新预览；
   - **确认后整套文字样式特征冻结保存**（`optimized_params`）：该选区的字号 / 字间距 / 笔画粗细 / 颜色 / 倾斜 / 质感全部锁定，之后**重开该框仅编辑文字内容、原有样式不被重新计算或覆盖**；
   - 可随时点 **「清空文字」** 重置；**保证每个选区独立运行**，互不继承、互不覆盖。
   **第四步（自动二次排版优化）：对齐周边风格**
   - 确认后自动微调**首尾字符 / 整体布局**：字号若与四向参照偏差 >15% 取均值收敛；`letter_spacing` 收敛到 `[-5, 40]` 合理区间，使新文字自然融入周边排版；
   - **字间距严格等于原图实测间隙（用户硬性要求）**：用 `_calibrate_letter_spacing` 闭环校准——渲染一次、量一次可见间隙、按差值反推 `letter_spacing` 修正（与具体替换字体无关），无论键入字数如何变化、换成哪款字体，替换文字的「字与字距离」都与原图逐像素一致（量化极限 ≤1px）；**字数变化只改变整段宽度，绝收放字距**，**字号 / 笔画粗细 / 基线保持锁定不变**。
   **第五步（渲染防重叠 → 预览导出）**
   - 完整提取视觉参数后自动匹配字体并渲染（含字形覆盖校验、字重选字对齐、自动模糊/噪点质感融合）；
   - **允许新文字超出选框，但禁止与原有文字重叠**：用 `neighbor_boxes` 做重叠检测，先在上下、再在左右逐级搜索空位，仍重叠则按 `1.0→0.92→0.85→0.78→0.7` 缩放字号继续避让，**绝不压到原图文字**；
   - 渲染结果实时进入底部预览面板，可 **「应用替换」** 写入工作图、**「保存图片」** 导出。
4. 在 **「替换文字」** 输入框键入新文字后点击 **「确认替换文字」**，底部预览面板**实时刷新**——无需任何手动操作即可看到接近原图质感、且**不与周边文字重叠**的结果。
5. （可选精修）从右侧 **「候选字体」** 点击选择另一款；或用滑杆微调字号、字间距、行间距、倾斜、清晰度、模糊、边缘柔化、噪点、擦除强度、不透明度；**「加粗」复选框仅作为手动叠加覆盖（默认关闭；字重已由程序按原图实测笔画厚度自动选字对齐，绝不强行加粗/加细）**；用「吸管」取色校正颜色。任何时候点 **「恢复自动参数」** 即可回到自动提取的最优值。
6. 满意后点 **「应用替换」** 写入到工作图（可多次框选多次应用）。
7. 点 **「保存图片」** 导出（程序会自动应用尚未提交的预览，避免丢修改）。


### 5.3 关键交互

- **参数联动预览**：调字号/颜色/间距等滑杆时，底部预览面板 200ms 内自动刷新，无需手动点「预览」。
- **预览 vs 应用**：「预览」只更新右侧预览面板，不改工作图；「应用替换」才把预览结果写入工作图并加入撤销栈（之后可撤销 / 恢复）。
- **保存时自动应用**：若点保存时还有未应用的预览，程序会先自动应用，确保导出图包含全部修改。
- **多次框选（多区域独立编辑）**：同一张图可以反复框选不同区域，**每个选区独立记住自己的替换文字/字体/参数**；在某一框输入文字正在预览、还没点「应用替换」就去画下一处时，程序会先把上一框的草稿**自动固化**进工作图，因此**上一处的修改不会消失、也互不覆盖**；切回任一框也能恢复它自己的文字与字体继续编辑。
- **选区二次编辑（8 锚点 + 长摁移动 + 叉号）**：拖**四角锚点**斜向缩放、拖**四边中点**单独调高/调宽（缩放松手自动按新位置重新擦除+提取+匹配）；**长摁（260ms）或明显拖动选框中间**整体移动（单击框内=编辑文字、不误移，所有框——含已确认框——都支持）；**长摁移动松手**后右上角出现圆形**叉号**（此时锚点收起），点叉号删除该框；**单击选框**则恢复锚点、隐藏叉号。
- **新建选框即去除底字**：框选一片区域、松手即把被遮住的原文字从工作图**擦除并固化**——无需输入替换文字或点确认。之后**删除 / 移走 / 缩放选框，原文字都不再出现**（旧位置保持已擦除、新位置也同步擦除），**只有「撤销」（Ctrl+Z）能恢复**。框在纯背景（无文字）区域不会误擦。
- **四边延长辅助线**：活动选框的上下左右四条边向画布两端延伸出贯穿虚线参考线，方便把选框的行列与周围文字上下文对齐。
- **擦除严格限制在选框内（本轮变更）**：擦除范围**就是选框矩形本身**，不再取「原文字真实墨迹 ∪ 选框 ∪ 替换文字占位」的并集——旧实现为了防残字会**越出选框**擦除，把框外的上下文文字/纹理一并抹掉，用户明确不接受。现在框内才擦、框外零改动。
- **消除原图文字只在两个时机生效**：① **新建选框**（松手即擦并固化）；② **移动选框**（旧位置 + 新位置的框内各擦一次）。**缩放选框（拖 8 锚点改尺寸）不擦除**，点选/重选/预览/应用也都不擦除。
- **复制选框不擦除**：副本由程序摆到原框右侧（或下方），落点底下盖的是别处原图内容，沿用「新建即擦除」会凭空抹掉一块无关画面；复制后只有用户**主动移动**副本时，才按「移动」规则擦除。
- **预览「井」字辅助线（只画在预览上）**：输入替换文字时，预览界面用**四根两端延长的直线**围住替换文字，相邻直线在四角**相交**、整体呈「井」字形，方便对照上下文对齐。辅助线**只画在预览的显示副本上**，确定替换后**绝不会出现在效果图 / 导出图**中。
- **复制选框（`Ctrl+D` / 工具栏「复制选框」）**：把当前选框**连同它的编辑文字与字体特征一起复制**——新框自动放到原框右侧（放不下则下方，并夹在图像内），成为当前框，并完整继承原框的替换文字、所选字体、已校准特征（字号/笔画/颜色/倾斜…）与确认冻结的排版参数，因此复制出的效果与原框完全一致。复制体**先可拖动定位**，点一次「确认替换文字」落地后清除 `_copied` 标记（此后与其它框一样：单击编辑文字、长摁仍可移动选框）；四向参照按**新位置**重新采集，保证防重叠判定仍准确。原框及其状态不受影响（两框深拷贝、互不影响）。
- **确认后样式锁定（重开仅编辑文字）**：点「确认替换文字」后，该选区的整套样式特征（字号 / 字间距 / 笔画粗细 / 颜色 / 倾斜 / 质感）**整体冻结保存**；之后再次点开该框**只恢复并允许编辑文字内容，原有样式不再重新计算或重排**，所见即所得、不会漂移。
- **切框不回弹（各选区数据互相独立）**：切换 / 新建选框时，当前框的草稿会先固化进工作图，且每个框的 `_locked` / `optimized` / `neighbor_ref` / `neighbor_boxes` 等状态**全部独立保存、互不覆盖**；切换到其它框不会改动已确认框的效果，防重叠信息也随框保留，不会丢失。
- **一键回自动值**：手动调乱参数后，点「恢复自动参数」即可回到本帧自动提取的最优值。
- **参数微调面板可折叠**：右侧「参数微调」面板默认展开，全自动模式下通常无需展开；点标题栏可折叠/展开，仅在需要手动覆盖时才展开精修。
- **撤销 / 恢复（互为逆操作）**：按 `Ctrl+Z` 或点「撤销」逐步回退；按 `Ctrl+Y`（或 `Ctrl+Shift+Z`）、点「恢复」把刚撤销的那一步**原样找回**——图像、各框的文字/字体/冻结排版参数、甚至被丢掉的未提交草稿都一起回来。产生新的提交（应用替换 / 新建擦除 / 移动擦除）或框集合变化（删除·复制·清空选框）后，恢复栈按标准语义清空。
- **删除选区**：按 `Delete` 删除当前选中的框，便于去掉误框的区域。

### 5.4 框选小技巧

- 框选范围比文字稍大一点（上下左右各留 2~5px 空白），擦除效果更好。
- 单行文字直接框整行；多行文字整段框选（程序会自动识别行数）。
- 框选错了就重新框一次，旧框选会自动取消。

## 七、常见问题（FAQ）

**Q1：滚轮缩放没用？**  
请把鼠标光标放在画布区域内再滚动。程序会在画布区域捕获滚轮事件。

**Q2：右键拖动没反应？**  
确保点的是鼠标右键（不是左键），且光标在画布上。

**Q3：识别不出我的字体？**  
本工具只能在内置免费字体库中匹配，不识别小众/付费/艺术变形字体。若原字体不在库中，只能选最接近的替代字体。

**Q4：擦除后留下明显的矩形痕迹？**  
复杂背景、低清晰度截图、强压缩图片无法做到 100% 无痕。可尝试提高「擦除强度」，或缩小框选范围更贴近文字。

**Q5：新文字位置/大小对不齐？**  
优先微调「字号」「字间距」「行间距」，并用「倾斜角度」对齐原文字。

**Q6：颜色不准？**  
用「吸管」点击原图文字像素手动校正（**注意：左键单击不拖动才会触发吸管**）。

**Q7：为什么候选字体里没有中文字体（或没有英文字体）？**  
程序根据你输入的新文字自动判断中/英文，优先展示对应语言的字体。若系统缺少对应字体，可手动放入 `fonts/` 目录。

**Q8：调参数后预览没刷新？**  
参数变化会在 200ms 内自动刷新预览（防抖）；如果实时调整很频繁，可在调好后稍等一会，或直接点「应用替换」强制写入。

**Q9：保存出来的图是原图？**  
如果只点了「预览」没点「应用替换」就保存，程序会在保存前自动应用未提交的预览，确保导出图包含全部修改。

**Q10：程序打不开 / 报错缺少模块？**  
确认用标准安装版 Python（带 tkinter）运行，并已执行 `pip install -r requirements.txt`。

## 八、限制说明（重要）

1. 本工具只能在**内置常用免费字体库**中进行相似度匹配，不做全网字体识别。
2. 不能精准识别小众字体、付费商用字体、以及被拉伸/变形/艺术化的字体。
3. 如果原图字体不在内置字体库中，只能选择最接近的替代字体。
4. 复杂背景、低清晰度截图、强压缩图片，无法做到 100% 无痕。
5. 最终效果依赖用户预览和手动微调。
6. **字重（笔画粗细）通过「选字」对齐，而非事后描边**：程序按原图实测笔画厚度（px）在字体池中挑选天然字重最接近的字体，渲染阶段**不施加任何描边**——既不强行加粗、也不强行加细。受 Pillow 限制，程序**无法把字体调细**，因此若原图比字体池里最细的候选还细，会以最接近者渲染（不强行加粗）；若原图比池里最粗的候选还粗，同样以最接近者渲染。想要更精确的字重，往 `fonts/` 目录放入粗细梯度更丰富的同款字体即可。
7. **OCR 识别为离线增强、可降级**：选区文字识别依赖本地 RapidOCR 引擎（随依赖安装，模型内置于包内，无需联网下载）。OCR 仅在新建选区时触发，识别结果作为默认替换文字，用户仍可手动覆盖；若环境未安装 RapidOCR，程序**不会崩溃**，自动退化为手动输入，后续擦除/特征/渲染/导出全部照常。
8. **上下行参照校准以段落上下文为准**：第二步会截取选区紧邻的上下一行做对齐。若选区本身已位于段落首行/末行（无紧邻文本行），则自动退化为仅用选区自身特征，不影响正常使用。

## 十一、技术实现要点

- **GUI**：tkinter + Canvas 自绘，支持**滚轮锚点缩放**（光标位置固定）、**右键平移**、**左键框选**；已选区带 **8 个锚点（四角 + 四边中点）可缩放**（拖四角斜向缩放、拖上下边中点改高度、拖左右边中点改宽度）；**长摁（260ms）或明显拖动（>5px）选框中间可整体移动**；单击框内 = 选中编辑文字、显示锚点；长摁移动松手后右上角出现叉号（点击删除该选框，替换结果保留、仍可撤销）。
- **双缓冲**：每帧先把「图像 + 选区框 + 手柄」画到离屏 `PIL.Image` 缓冲，再一次性贴到画布上唯一的 image item，彻底消除黑屏/闪烁/卡死/图像消失。
- **视口裁剪**：放大时只把当前可见区域生成 PhotoImage，平移/缩放时增量重绘，避免内存爆炸（OOM）。
- **图像处理**：OpenCV（inpainting、Canny、距离变换、Laplacian、高斯模糊）、Pillow（文字渲染、字体测量）、numpy（像素矩阵）。
- **颜色提取**：k-means 聚类 + 与背景亮度反差取主色；支持吸管校正与颜色选择器。
- **字号估算（字符级墨迹高度）**：二值化后按行投影拆行、列投影拆字符，逐字量取墨迹竖直跨度、取中位数作为真实像素字号；渲染时再按目标文本首行真实墨迹反推 em 字号（`ImageFont` 的 size 是 em，真实墨迹仅占 0.7~1.0），**确保新文字字号与原图字符实际占用像素空间精准对齐、不偏大不偏小**。
- **字间距**：按列统计相邻字符间空白宽度中位数。
- **清晰度**：拉普拉斯方差（Variance of Laplacian）归一化。
- **粗细（骨架细化算法）**：Zhang-Suen 骨架细化得到单像素宽的笔画中心线，**笔画厚度 = 前景像素总面积 ÷ 骨架中心线长度**（即平均笔画宽度）；该骨架口径与距离变换口径双路加权，用于字体字重匹配（用户硬性要求：用骨架算法算笔画厚度，保证新文字粗细与原图一致）。
- **倾斜**：轮廓 minAreaRect 角度，叠加前景像素协方差 PCA 主轴方向交叉校验（对单/少字符、minAreaRect 退化为 0 的情况更敏感）。
- **模糊/抗锯齿/噪点**：模糊=对比模糊前后灰度差；抗锯齿=边缘半透明像素占比；噪点=高频残差能量，三者共同驱动渲染后处理。
- **自动模糊/噪点质感融合**：特征提取得到模糊度（`blur_level`）、噪点（`noise_level`），全自动模式下直接驱动渲染后处理——新文字自动叠加与原图一致的失焦模糊与截图颗粒感。渲染层**不再受清晰度（sharpness）门控**，模糊必然施加（修复了旧版自动模式下模糊永远到不了渲染层的 BUG）。
- **基线对齐 + 墨迹对齐**：渲染时按原文字墨迹包围盒修正 Y 偏移，避免新文字上下错位；同时按真实墨迹高度反推字号，确保新文字与原图字符占据的像素空间一致。
- **字体匹配**：以「原图实测笔画厚度（字重）」为最高权重，再综合「每字平均宽度（宽窄留白）」与「字形覆盖率/宽高比」计算相似度，自动选最高分；字重通过选字对齐，渲染阶段不描边。全自动模式下无需用户点选。
- **字体匹配用连续 em 窄窗微扫描（修复「骨架口径选字选错」）**：FreeType 按像素栅格拟合，使「骨架厚度 vs 字号」呈**阶跃函数**（实测 msyh 在 em≥47.5 跳变到 3.43、em<47.5 仅 3.21）。em 推定四舍五入成整数时可能正好落在跳变悬崖错误一侧（msyh@48 估出 47.499→47），导致雅黑被误判成黑体。修复：`feature_extract` 抽出 `_estimate_em_core`/`estimate_em_continuous` 暴露**连续 em**；`font_match` 不再在单一整数 em 上量候选，而是围绕连续 em 做 `±2.5em`、步长 `0.5` 的窄窗微扫描，每候选取最贴近目标骨架的读数——稳定跨过栅格化台阶，字体自匹配率回到 100%。
- **离线 OCR（先识别）**：`app/ocr.py` 封装 RapidOCR 为可选增强。`is_ocr_supported()` 仅探测 import（不加载模型）；`ocr_region()` 懒加载引擎并缓存单例、返回识别文字（0.5 置信度过滤）、任何异常返回 `""` 不崩溃。引擎已内置于 RapidOCR 包内，无需联网下载，满足离线运行。
- **OCR 小图放大（提升小字识别率）**：`gui.on_box_selected` 在识别前若选区图像高度 `<40px`，先 `cv2.resize` 放大（`INTER_CUBIC`）再做 OCR，显著缓解识别不准；放大仅用于识别，不影响后续特征与渲染坐标。
- **四向参照校准（再校准）**：`feature_extract.extract_neighbor_reference()` 按选区字号估计行高/字宽，截取**上 / 下 / 左 / 右**四个紧邻文字窗口各自独立 `extract_features`，仅保留含文字的参照（无文字方向跳过、不越界），融合字号/字间距/笔画粗细/模糊/噪点并约束在合理区间；同时回传各命中窗口文字的**整图坐标矩形**（`neighbor_boxes`）供防重叠使用。
- **强制五步顺序（识别→采集特征→用户确认→二次排版→防重叠渲染）**：`gui.on_box_selected` 对新建选区依次执行 ① OCR 识别本选区文字填入输入框（不继承、不覆盖用户已改字）+ 采集文字主要特征并应用到新文字 + **特征锁定 `_locked`**（与选框位置一同固定，重选/缩放只恢复、绝不重识别）；② 用四向参照校准排版/质感参数；③ 用户在输入框键入文字并点「确认替换文字」（`_confirmed=True`）；④ `_calibrate_letter_spacing` 闭环校准字间距严格等于原图实测间隙（不参考邻居、不按宽度收放）；⑤ `_do_render(optimize=True)` 走防重叠渲染。`on_box_select_same`（重选已有框）恢复该框已存 OCR 文字/校准特征/四向参照、不再重新识别。
- **特征锁定（`_locked`）**：新建框完成识别+特征采集后立即冻结，缩放（`on_box_changed`）时仅恢复锁定特征、刷新四向参照、刷新预览，**绝不重新识别或重提取**，保证特征稳定、位置固定。
- **防重叠渲染（`_place_anti_overlap` + `_overlaps_any`）**：确认后渲染允许新文字超出选框，但禁止与 `neighbor_boxes` 中任一原图文字矩形重叠——先上下、后左右逐级搜索空位（步长 4px），仍重叠则按 `1.0→0.92→0.85→0.78→0.7` 缩放字号继续避让，best-effort 降级也绝不压到原图文字。
- **字号匹配周边像素尺寸（修复「生成文字偏小」）**：`estimate_font_size` 直接返回**字符级真实墨迹像素高度**作为目标字号，渲染侧再据该高度反推 em 字号——去掉了原先重复的 `×0.96` 压缩（渲染侧本就做墨迹→em 反推，再压缩等于双重打折），使生成文字墨迹高度 ≈ 原图真实像素尺寸，不再偏小。
- **笔画粗细以选区自身为主（修复「笔画粗细不一致」）**：四向参照校准笔画（`stroke_px` / `stroke_px_skeleton` / `stroke_weight`）改为**以选区自身实测为主（0.7）、邻居参照为辅（0.3）**，避免邻居把笔画粗细拉离被替换文字的真实粗细，生成笔画与原文一致。
- **确认后参数冻结 + 重开复用（修复「切框回弹 / 样式漂移」）**：`_confirm_text` 把闭环校准后的**最终参数整体冻结**为 `optimized_params`；之后重渲染（重开 / 改字）若 `optimized_params` 存在则直接复用，渲染路径仍会调用 `_calibrate_letter_spacing` 做一次严格对齐校验（结果与原图间隙一致即不再改动），原有样式稳定不被重算覆盖。
- **字间距严格等于原图实测间隙（用户硬性要求，本轮修复「识别原图没识别字与字距离」）**：`_calibrate_letter_spacing(text, params, font_path)` 用**闭环校准**——先取原图实测字符间隙 `features["letter_spacing"]`（`estimate_letter_spacing` 按列投影测相邻墨迹间空白列宽中位数；此前该函数有 bug 永远返回 1，致使 app 从未真正读到原图字距，这是「字距对不齐」的根因，已修），再渲染一次、量一次真实可见间隙、按差值反推修正 `letter_spacing`（可见间隙 ≈ letter_spacing + 字体侧边距偏移，线性关系一遍收敛）。**无论键入字数如何变化、换成哪款字体，替换文字字与字距离都与原图逐像素一致（整数像素量化极限 ≤1px）**；用户若手动拖过字间距滑块则以手动值为准（优先级最高）。**字数变化只改变整段宽度，绝不收放字距**；字号 / 笔画粗细 / 基线保持锁定不变。
- **`apply_replace` 合并写入（修复「切框数据丢失 / 回弹」）**：固化当前框草稿时由「整体覆盖 `box_edits[idx]`」改为「合并写入」，保留该框已锁定的 `_locked` / `optimized` / `neighbor_ref` / `neighbor_boxes` / `optimized_params`，确保切换选框后上一框效果与防重叠信息不丢失、各选区数据互相独立。
- **撤销 = 「图像 + 各框编辑状态」一并入栈（修复「撤销无效 / 撤销后又变回来」）**：撤销栈的每个元素是历史帧 `{"bgr": 该次提交后的图像, "box_edits": 各框编辑状态快照}`。撤销时**同时**还原图像与框状态，并清空输入框残留文字——否则已撤销的替换会在重新点选/缩放该框时被重新渲染出来（只回退图像的旧实现正是「撤销了又回来」的根因）。未点「应用」就按撤销时（`history` 仅剩初始帧）则把「确认/预览草稿」整体丢弃（不再弹「没有可撤销的操作」）。每点一次「应用替换」、离开当前框自动固化、保存前自动固化都会各提交一帧，可逐级撤销。
- **确认/切换字体即写回框状态（修复「切换字体后点确定又变回原效果」）**：`_confirm_text` 与 `_select_candidate` 都把 `selected_font_path` 写回 `box_edits[idx]["font_path"]`。此前只有键入与「应用替换」会写回，若用户「切字体 → 确认」后重选该框，恢复路径读到旧字体，效果被打回创建时原状——现确认与切换即持久化，重选/缩放/离开再回都不再回退。
- **恢复（redo，本轮新增）：与撤销严格互逆**：`redo_stack` 逐帧保存被撤销掉的「图像 + 各框编辑状态 + 未提交草稿（`pending`）」。`undo` 的两种情形（回退已提交帧 / 丢弃未确认草稿）都会把被撤销的状态压栈；`redo()` 出栈后重新入历史栈、还原图像与框状态、同步输入框文字，所以「恢复了但框状态是空的」不会发生。产生**新的**历史帧（`apply_replace` / `on_box_create` / `on_box_edit_start`）或框集合变化（删除·复制·清空选框）时 `redo_stack` 立即清空——与通用 redo 语义一致。栈空时只弹提示，绝不抛异常。入口：工具栏「恢复」按钮 + `Ctrl+Y` / `Ctrl+Shift+Z`。
- **手调过的字号不再「确定后跳变」（本轮修复）**：根因是已确认框的预览直接沿用冻结的 `optimized_params`，用户手调字号后**预览毫无反应**，一点「确认替换文字」才突然跳到新大小（用户报「确定后大小变了」）。修复：`_manual_font_size(idx)` 取用户手动拖过的字号，**优先级高于冻结参数 / 自动识别值**——`_do_render` 的 optimize 分支一律以手调值为准，并让它与「确认」走**同一套间距校准**（`_calibrate_letter_spacing`），`_confirm_text` 冻结的也就是用户当时所见的值。于是：手调 → 预览当场生效，确认前后**零跳变**；移动/重开选框仍保持手调值（不被识别基线打回）。未手调时行为完全不变（仍走自动识别字号）。
- **空框不自动固化「只擦除预览」（修复「随手框一下就擦掉原文」）**：没有替换文字且从未确认的框不再生成只擦除的中间预览（`_refresh_preview` 遇空内容直接显示工作图）；即便产生草稿，「离开当前框/保存」的**静默提交**也只在本框确有文字或已确认内容时才执行——空框误擦原文既不会发生，也不再污染撤销栈。
- **选框移动 / 缩放 / 删除交互（本轮新增）**：画布命中新增 `("move", ...)` 态 + 长摁状态机（260ms 或拖动 >5px 进入移动）。**所有框（含已确认）都可长摁/拖动整体移动**——取消早期「确认后位置锁死」（否则已确认框永远拿不到右上角叉号）；单击框内 = 选中编辑文字、不移动（防误触）。8 锚点拖拽缩放（四角斜向、四边中点改单边尺寸）。**右上角叉号**：仅「长摁移动松手」后出现、此时收起四角锚点；单击选框则反之（显示锚点、隐藏叉号）；点叉号 = 删除该选框（替换结果保留、仍可撤销）。**替换结果持久化**：移动/缩放/删除的几何改变前，先把「已擦除」固化进工作图（`on_box_edit_start`），原文字此后永不再复活（删除/移走选框都不出现，仅「撤销」可撤回）；空框（未改字、未确认）绝不误擦原文。
- **离开当前框前先同步补渲染（修复「画新框后上一框替换文字消失」）**：旧 `on_leave_box` 只在 `pending_result` 已生成时才固化；若键入文字后立刻去画新框（300ms 防抖预览未跑），草稿只存在于 `box_edits`，画布上上一框的替换不显示，必须重新点回。现在离开前若框内有草稿但无预览，先同步调用 `_refresh_preview()` 补出结果再 silent-apply；同时画布「点空白/点其它框/新建」都会先触发离开固化（不再只命中其它框才固化）。
- **确认即闭环校准字间距严格对齐原图（修复「识别原图没识别字与字距离」）**：`_confirm_text` 冻结 `optimized_params` 前先执行 `_calibrate_letter_spacing(text, params, font_path)`——以原图实测字符间隙（`features["letter_spacing"]`）为目标做闭环校准，使替换文字可见字距与原图逐像素一致；叠加渲染侧的基线对齐与墨迹中心对齐，新文字首尾与原字平齐、与上下文自然衔接。此前旧实现按「原文字像素跨度」反推字距（字数一变就收放、且 `estimate_letter_spacing` 有 bug 永远返回 1），导致替换字距与原图根本对不齐。
- **紧凑结构字 em 不塌缩（修复「结构紧凑的字识别偏小」）**：汉字上下堆叠结构（赢=亡口月贝凡、臝、鬱…）内部有**整行全空**的留白，行投影会把它切成一叠小“行”，em 被低估 22%~54%（实测「赢羸蠃臝」@48 只估出 22~37）。`_estimate_em_core` 先做**小间隙行段合并**：相邻段墨迹间隙 ≤ max(2, 0.30×段高) 且 x 方向交集 ≥60% 即并回同一行——字内留白被吸收，正常行距（间隙 ≥0.4em）不会被误并。
- **手动字号确认后仍生效（修复「微调字号后确定又变回识别大小」）**：闭环校准 `_calibrate_letter_spacing` **不再参考邻居字号取平均/覆盖**（曾把 30 与邻居 50 平均成 40，或把手动放大值拉回识别值）；字距严格由 `_calibrate_letter_spacing` 对齐原图实测间隙，不照搬邻居、不按宽度收放。重选已确认框时字号滑杆显示该框**实际使用**字号（而非创建时识别值），再微调不会被“恢复自动值”打回。
- **渲染不再自动缩小字号（修复「字总被自动缩小/放大后文字跑框外」）**：`_do_render` 删除 1.0→0.92→0.85→0.78→0.7 的逐档缩小；确认渲染始终使用设定字号。防重叠改为**距离优先的位置避让**：以基础位置为中心按位移由小到大搜索最近空位（旧实现先垂直盲扫 ±80px，可能把整块文字挪得很远、看起来“跑到选框外面”），实在无空位则原地尽力放置。
- **em 推定只统计满高字形（修复混排文本字号被低估、字体匹配扫描中心错位）**：`_estimate_em_core` 按列拆字符后**剔除高度 < 0.78×行内最大高的字形**（数字 ~0.7em、小写拉丁 ~0.5em、标点被剔除，汉字与满高全角标点保留）。此前混排文本「2026年第3期」@48 的 em 被低估到 39px（-19%），连带字体匹配错位。只能按**高度**过滤、不能按宽度过滤——「国」「测」等合体字会被列投影拆成「高而窄」的碎片列，按宽度剔除会让字宽通道(C)标定口径失配而高估 em。
- **字体匹配不再叠加 aspect 判据（修复含竖缝合体字/标点文本选错字体）**：原图侧靠列投影拆字的宽高比会把「细=纟+田」「测=氵+则」拆成窄碎片（target 0.979 vs 整字 0.989，偏差 0.01~0.2），比雅黑/黑体近缘字本身的真实差还大；实测叠加 aspect 打分使 64 个含标点/数字/中英混排样本的自匹配率从 100% 降到 97%。字重（骨架口径 + em 窄窗扫描）是唯一决定性判据。
- **复制选框（功能）**：`copy_selected_box(target_box=None)` 对当前选框做**整份状态深拷贝**（`text` / `ocr_text` / `font_path` / `features` / `optimized_params` / 确认状态）并追加一个新框，因此复制体与原框的替换内容与字体特征完全一致、且两框互不影响（深拷贝）。不传 `target_box` 时落点优先原框右侧、其次下方；传入时副本直接落到该处（拖拽复制用）。落点始终夹在图像内；因为位置变了，四向参照按**新位置**重新采集（防重叠用），而本框特征仍锁定不重识别。复制体带 `_copied` 标记——允许先拖动定位（沿用「确认前可移动」规则），点一次「确认替换文字」后清除该标记（此后与其它框一样：单击编辑、长摁仍可移动）。
- **复制选框不消除原图文字（用户硬性要求）**：复制**不是**「新建选框」也**不是**「移动选框」，因此不触发 `on_box_create` / `on_box_edit_start`，**全程不擦除任何原图内容**——副本落点下方盖着的往往是别处的画面，沿用「新建即擦除」会凭空抹掉一块与本次替换无关的内容。判据：复制前后落点区域像素逐字节一致（见 `test_space_right_drag_copy` 的红字计数 + 逐字节对比）。复制后用户**主动移动**副本时，才按「移动」规则擦除（那是用户明确把框摆到新位置）。
- **触发方式改为「按住空格 + 右键拖拽选框中间」（本轮变更）**：`ImageCanvas` 新增 `space_held` 状态（App 用 `<KeyPress-space>` / `<KeyRelease-space>` 维护；**焦点在输入框时不拦截**，保证打字正常）。`_pan_start` 在 `space_held` 且右键命中选框内部（`move` / `select`）时进入复制态：先按左键同一套顺序「离开固化旧框 → 置活动框 → 恢复该框状态」完成**选中**，再随右键拖动用 `_offset_box` 算落点并画**青绿色虚线幽灵框**预览；`_pan_end` 松手时回调 `on_copy_box_to(src_idx, target_box)` → `App.copy_selected_box_to()` 在落点直接建副本。**不按空格时右键仍是平移画面**；点在空白 / 锚点 / 叉号也不触发复制（都不进入复制态）。
- **擦除严格限制在选框内 + 只在新建/移动时生效（本轮变更）**：`_erase_region_for` 现在**只返回选框矩形本身**（越界夹取到图像内、反序框归一化），不再取「原文字真实墨迹 ∪ 选框 ∪ 替换文字占位」的并集——旧实现为防残字会越出选框，把框外上下文一并抹掉。`_text_extent_region`（从原图用 Otsu 探查文字真实墨迹范围）**降级为诊断工具，不再参与任何写图路径**。
  触发时机收口为两个入口：
  · `on_box_create`（**新建选框**松手即擦，仍排在 OCR/特征/字体匹配长链路之前，识别崩了字也照样删掉）；
  · `on_box_edit_start(..., mode="move")`（**移动选框**：拖动首帧固化旧位置、松手时擦新位置）。
  画布侧把 `move` / `resize` 模式透传下来，`mode != "move"`（即**缩放锚点**）直接 return，**不擦除**。`copy_selected_box` 已移除 `on_box_create` 调用，**复制选框不再擦除**；复制后用户主动移动副本时，仍按「移动」规则擦除。
- **预览「井」字辅助线（本轮新增）**：`_draw_preview_guides` 沿替换文字墨迹的上/下/左/右边界画四根**两端延长**的虚线，相邻两根在四角相交、整体呈「井」字形，便于对齐上下文。关键安全约束：预览裁剪图是 `pending_result` 的 numpy **视图**，直接在其上绘图会顺着视图写回底层图像、被「确定替换」一起提交甚至导出；因此 `_preview_display_image` 一律先 `crop.copy()` 再画，**显示层与数据层物理隔离**。
- **颜色通道不再互换（Bug 修复）**：`render.composite_text` 此前把 PIL 渲染出的 **RGB** 层直接混合进 OpenCV 的 **BGR** 底图，导致**要蓝字出来红字、要红字出来蓝字**（黑白灰因三通道相同才一直没暴露）。现按 `sub[:, :, 2::-1]` 翻转通道后再混合，并加了红/蓝双向回归守卫。
- **移动/缩放选框不改动用户已调好的文字参数（本轮修复）**：用户手动把字号调大后，一旦移动选框（或点选该框）字号就被打回 OCR 识别基线——根因是「恢复框基线特征」（`on_box_select_same`/`on_box_changed`）会把滑块整体写回旧基线。修复：新增 `_user_tweaks` 记录**用户手动调整项**（滑块值快照，按框索引保存；删除/复制/清空选框时同步维护），恢复基线后把手动项重新盖回滑块。**移动/缩放/点选都不再覆盖用户调好的字号、字间距、笔画粗细等**；自动特征提取（`_set_slider`）不经 `_on_slider`，不会被误记为手动调整。
- **路径兼容**：`cv2.imencode/imdecode + numpy.tofile/fromfile` 间接实现中文路径读写。
